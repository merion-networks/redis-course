### Домашнее задание: Система лайков
#### Цель:
Расширить базовое приложение FastAPI, используя Redis для кэширования, реализации системы лайков и ведения истории просмотров, а также обеспечить работу с аутентификацией пользователей.

#### Задачи:

1. Аутентификация и сессии:
   - Создайте зависимость `get_current_user`, которая будет извлекать сессионные данные из Redis на основании заголовка `Authorization: Bearer <token>`. Если токен недействителен или отсутствует – возвращайте ошибку 401.

2. CRUD для постов:
   - Реализуйте эндпоинты для создания, получения, обновления и удаления постов.
   - При создании поста, автором должен становиться текущий аутентифицированный пользователь (поле `author_id`).
   - Обновление и удаление поста должны быть доступны только его автору.

3. Кэширование и история просмотров:
   - При получении поста (GET `/posts/{post_id}`) используйте Redis для кэширования результата (ключ вида `post:{post_id}`).
   - Если пользователь аутентифицирован, добавляйте ID просматриваемого поста в историю просмотров в Redis (используйте список с ключом `views:{user_id}`).
     - Используйте команду `LPUSH` для добавления нового просмотра.
     - Ограничьте длину списка до 10 последних просмотров с помощью `LTRIM`. *
   - Реализуйте отдельный эндпоинт (например, GET `/posts/views/history`), который будет возвращать историю просмотров текущего пользователя – список постов (не только ID).

4. Система лайков с использованием Redis Sets:
   - Реализуйте эндпоинты для:
     - Постановки лайка: (POST `/posts/{post_id}/like/`) – добавляет идентификатор текущего пользователя в Redis-множество для данного поста (ключ `likes:{post_id}`) с помощью команды `SADD`.
     - Отмены лайка: (POST `/posts/{post_id}/unlike/`) – удаляет идентификатор пользователя из множества (команда `SREM`).
     - Получения количества лайков: (GET `/posts/{post_id}/likes/`) – возвращает число элементов в множестве (`SCARD`).
     - Проверки лайка: (GET `/posts/{post_id}/likes/check/`) – проверяет, содержится ли идентификатор текущего пользователя в множестве (команда `SISMEMBER`).

5. Дополнительные требования:
   - Порядок маршрутов: Обратите внимание на порядок объявления маршрутов (например, маршрут `/posts/me` должен быть объявлен до маршрута `/posts/{post_id}`, чтобы избежать ошибок при парсинге параметров).
   - Документация: Все эндпоинты должны быть задокументированы (FastAPI автоматически генерирует документацию Swagger, убедитесь, что описания и типы параметров корректны). *
   - Обработка ошибок: При отсутствии поста, пользователя или недействительном токене – возвращайте соответствующие HTTP ошибки с подробным сообщением. *

#### Рекомендации:

- Используйте код из уже выполненного задания как отправную точку.
- Применяйте команды Redis для работы с множествами (`SADD`, `SREM`, `SCARD`, `SISMEMBER`) и списками (`LPUSH`, `LTRIM`, `LRANGE`).
- Проверьте работоспособность каждого эндпоинта с помощью Postman.

Итог:  
В результате выполнения домашнего задания приложение должно позволять:

- При просмотре поста, если пользователь залогинен, автоматически записывать его ID в историю просмотров (с ограничением 10 последних просмотров).
- Ставить и убирать лайки постам, получать количество лайков и проверять, поставлен ли лайк текущим пользователем.
