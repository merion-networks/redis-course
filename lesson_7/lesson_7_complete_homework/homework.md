## Домашнее задание: Оптимизация операций в Redis с использованием Lua-скриптов, пайплайнов и MULTI/EXEC

### Цель

Расширить функциональность проекта, добавив оптимизированные операции в Redis:
- Использовать Lua-скрипты для выполнения нескольких команд.
- Применить пайплайны для массовых операций.
- Гарантировать атомарное выполнение группы операций с помощью транзакций MULTI/EXEC.

### Задачи

#### Задача 1. Lua-скрипт для атомарного обновления статистики просмотра

Сценарий:
При просмотре поста необходимо одновременно:
- Увеличить счётчик просмотров поста в отсортированном множестве (ключ `post:views:ranking`).
- Добавить ID поста в историю просмотров пользователя (список с ключом `views:{user_id}`) и ограничить длину истории (например, до 10 записей).

Требования:
- Напишите Lua-скрипт, который принимает три аргумента:  
  - `post_id` – идентификатор поста,
  - `user_id` – идентификатор пользователя,
  - `history_limit` – максимальное количество записей в истории просмотров.
- Скрипт должен атомарно выполнить следующие команды:
  1. Увеличить счётчик просмотров поста с помощью `ZINCRBY`.
  2. Добавить `post_id` в начало списка истории просмотров с помощью `LPUSH`.
  3. Обрезать список до `history_limit` записей с помощью `LTRIM`.
- Вызовите скрипт через команду EVALSHA из вашего приложения, интегрировав его в эндпоинт чтения поста.

#### Задача 2. Оптимизация массовых операций с использованием пайплайнов

Сценарий:
При симуляции массовых лайков (например, при заполнении тестовыми данными) требуется для большого числа операций поставить лайк для разных постов и обновить рейтинг авторов.

Требования:
- Реализуйте функцию, которая принимает список операций (например, каждая операция содержит `post_id`, `user_id` и `author_id`) и выполняет их через Redis-пайплайн.
- Для каждой операции добавьте команды:
  - `SADD` для постановки лайка (ключ вида `likes:{post_id}`).
  - `ZINCRBY` для обновления рейтинга автора (ключ `author:rating`).
- Используйте пайплайн, чтобы объединить все команды в один вызов к серверу Redis, тем самым снизив задержки.
- Протестируйте функцию, симулируя массовое обновление (например, для 100 постов).

### Критерии приёмки

- Корректность Lua-скрипта:  
  Скрипт должен атомарно обновлять рейтинг поста и историю просмотров. Результат выполнения скрипта должен подтверждать успешное выполнение (например, возвращать `true`). Скрипт должен загружаться из файла при старте приложения.

- Эффективность пайплайна:  
  Функция для массовых операций должна объединять все команды в один запрос и производить действия в рамках одной транзакции.
- Документация и тестирование:  
  Код должен быть хорошо прокомментирован. Результаты тестирования (например, логирование или вывод на консоль) должны подтверждать, что оптимизированные операции работают корректно.
