## Задание 1. Приложение с master-replica и Sentinel

Цель:  
Создать веб-приложение на FastAPI, которое работает в режиме master-replica с использованием Redis Sentinel. Чтение данных производится с реплики, запись – в мастер.

### Требования

1. Файловая структура и конфиги :
   - В корневой директории проекта должна находиться папка `configs/`, в которой будут располагаться все необходимые конфигурационные файлы для Redis, Sentinel или Docker (если используете контейнеры).
   - Пример возможных имён файлов в `configs/`:  
     - `redis_master.conf`  
     - `redis_replica.conf`  
     - `sentinel.conf`

2. Настройка Redis с Sentinel:
   - Поднимите (локально или через контейнеры) Redis мастер и одну (или нескролько) реплик.  
   - Настройте Sentinel так, чтобы он отслеживал статус мастера и реплик (например, укажите в конфиге мастера название и IP/порт).  
   - Проверьте, что при остановке мастера Sentinel определяет сбой и продвигает реплику в мастер (failover)

3. Разработка FastAPI-приложения:
   - Создайте приложение FastAPI с двумя эндпоинтами:
     1. `POST /set` (или `/write`): принимает ключ и значение, записывает в мастер .  
        - Должна выполняться именно запись в текущий мастер, адрес которого определяется через Sentinel (автоматически или через библиотеку, поддерживающую Sentinel).
     2. `GET /get` (или `/read`): принимает ключ и возвращает значение.  
        - Операция чтения должна идти к реплике (реплик), адрес которой также определяется Sentinel.
   - Файл с настройками (например, `config.py` или `.env`) разместите в корне проекта или продумайте способ хранить их в `configs/`.
   - Убедитесь, что при запуске приложения адреса (или хосты) Redis берутся из конфигов либо через Sentinel.

4. Тестирование работы:
   - Напишите краткое руководство, как поднять мастер, реплику и Sentinel.
   - Запустите приложение FastAPI, добавьте ключ через эндпоинт `/set` и убедитесь, что при считывании через `/get` данные возвращаются с реплики.
   - (Опционально) Остановите мастер и проверьте, что Sentinel выполнил failover – тогда приложение по-прежнему должно корректно работать при записи и чтении.

5. Документация и README:
   - Оформите README-файл с инструкциями по запуску Redis (мастер, реплика) и Sentinel, а также по запуску FastAPI-приложения.
   - Укажите, какие файлы конфигурации необходимо использовать (расположенные в `configs/`).

## Задание 2. Приложение с Redis Cluster (3 мастера, у каждого по 2 реплики)

Цель:  
Создать второе веб-приложение на FastAPI, которое работает с кластером Redis, состоящим из 3 мастер-нод и у каждой мастера по 2 реплики (итого 9 нод). 

### Требования

1. Файловая структура и конфиги:
   - Аналогично предыдущему заданию, конфигурационные файлы (при использовании Docker или отдельных инстансов) хранятся в папке `configs/`.
   - Пример возможных файлов:  
     - `redis_node_7000.conf`, `redis_node_7001.conf`, …  
     - Скрипт или инструкция по инициализации кластера.

2. Настройка Redis Cluster:
   - Поднимите 3 мастер-ноды (например, на портах 7000, 7001, 7002) и по 2 реплики для каждой (7003, 7004, 7005, 7006, 7007, 7008).  
   - Создайте кластер (командой вида `redis-cli --cluster create ...`) и убедитесь, что ключи шардируются.  
   - Проверьте, что у каждой мастер-ноды есть реплики.

3. Разработка FastAPI-приложения:
   - Напишите приложение FastAPI с тем же функционалом (как в первом задании), но теперь для взаимодействия с Redis Cluster:
     1. `POST /set`: запись ключа и значения.  
        - Redis самостоятельно определит, на какой шард отправить ключ.  
     2. `GET /get`: чтение ключа.  
        - Должна корректно выполняться маршрутизация на нужный шард.

4. Тестирование работы:
   - Создайте несколько ключей и убедитесь, что они распределяются по нодам (можно использовать `redis-cli --cluster check`).
   - Проверьте, что при остановке одной из мастер-нод происходит failover на её реплику.
   - Приложение при этом должно продолжить корректно работать при записи/чтении ключей.

5. Документация и README:
   - Оформите отдельный README-файл для второго приложения с инструкциями по запуску и инициализации кластера (9 нод).
   - Укажите пути к файлам конфигурации в `configs/`.
   - Опишите, как проверить, что кластер успешно распределяет ключи и как реагирует на сбои.

---

### Результаты и критерии приёмки

- Приложение 1 (Master-Replica + Sentinel):
  - Запуск Redis-мастера, одной или нескольких реплик, настроенного Sentinel.  
  - FastAPI-приложение с двумя методами `/set` (запись) и `/get` (чтение).  
  - Все конфигурационные файлы в `configs/`.  
  - При остановке мастера Sentinel выполняет failover, и приложение продолжает работать.

- Приложение 2 (Redis Cluster 3 мастера + 6 реплик):
  - Запуск 3 мастер-нод, у каждой по 2 реплики (итого 9).  
  - Скрипт или команда, формирующая кластер (`redis-cli --cluster create`).  
  - FastAPI-приложение с методами `/set` и `/get`
  - Ключи шардируются между мастерами, реплики синхронизированы, при сбое мастер-ноды – failover на реплику.

- Документация:
  - Чёткая структура README (или другого документа), описывающего процесс запуска Redis (Sentinel, Cluster) и самих приложений на FastAPI.
  - Пример тестовых запросов, проверяющих работоспособность обоих решений.
